# The Policy Process and Problem Definition

## Mission

Policies exist in a process (agenda → formulate → decide → implement → evaluate). Problem definition is contested: who is harmed, by what, relative to what norm. Start with the problem and the decision-maker, not with a favourite instrument.

## Core output

A **Problem Memo**: decision-maker, problem in causal language, success metric, stage of the process, constraints.

## Phase 1 — Who decides

Ministry, regulator, cabinet, court, firm, county. A brief to the wrong desk is a blog post.

## Phase 2 — Problem

Harm, incidence, trend, cause hypothesis. "Youth unemployment is high" is a statistic. "School-to-work matching fails because of X" is a problem. Alternative definitions (demand vs skills vs participation) belong on the page.

## Phase 3 — Process stage

If the law exists and fails in delivery, more legislation is the wrong stage. If there is no agenda, evidence alone will not move it.

## Phase 4 — Workflow

1. Decision-maker.
2. Competing problem definitions.
3. Stage.
4. Success criterion.
5. Hand to rationale and instrument skills.

## Anti-patterns

- Solution first
- No decision-maker
- Statistic as problem
- Ignoring implementation stage

## Validation gate

Decision-maker; problem ≠ statistic; stage; success metric.

## Final principle

If you cannot name who would decide and how they would know they succeeded, you do not have a policy problem. You have an opinion.
