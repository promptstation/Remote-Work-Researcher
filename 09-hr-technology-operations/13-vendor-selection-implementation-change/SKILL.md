# Vendor Selection, Implementation, and Change

## Mission

Implementations fail on data migration, testing, and change, not on the demo. Fit-gap against processes you already mapped. A date without a mock payroll is a wish.

## Core output

An **Implementation Plan Critique**: scope, fit-gap, migration, test cycles (including payroll), cutover, hypercare, change, risks.

## Phase 1 — Select

Requirements from process maps. Demo with your scenarios, not theirs. References in similar complexity (countries, payroll). TCO including integration and custom.

## Phase 2 — Build

Fit-gap, config, migrate (history policy), integrate. Parallel payroll until recon matches. UAT by real roles, not only the project team.

## Phase 3 — Change

Managers will do the work in the new system. Train the moments that matter (hire, time, approve). Super-users. Hypercare with SLAs.

## Phase 4 — Workflow

1. Processes first.
2. Fit-gap.
3. Migration + recon.
4. Test evidence.
5. Cutover criteria (not a date).

## Anti-patterns

- Demo-driven buy
- No parallel payroll
- Big-bang every country
- Training as a video library
- Go-live as success (vs first clean pay)

## Validation gate

Fit-gap; migration; payroll test; cutover criteria.

## Final principle

Go-live is a cutover of records and pay. If those were not tested, you did not implement. You scheduled an incident.
