# HR Process Automation and Case Management

## Mission

Automation amplifies the process you have. Case management makes work visible. RPA on a broken UI is glue. Chatbots that cannot escalate become complaint factories. Specify, then automate.

## Core output

An **Automation Decision**: process, volume, stability, tool (KB / case / RPA / bot), exception path, success metric.

## Phase 1 — Visibility first

Tickets with categories, SLAs, knowledge articles. If you cannot see volume, you cannot automate.

## Phase 2 — What to automate

High volume, low variation, clear rules (address change, employment letter). Not: grievances, complex pay, anything needing empathy and judgment — unless a human queue is the default.

## Phase 3 — Workflow

1. Process map.
2. Volume/variation.
3. KB then case then RPA/bot.
4. Escalation.
5. Measure deflection and rework, not only bot containment.

## Anti-patterns

- Bot as the front door with no escape
- RPA instead of an API
- Automating exceptions
- Success = fewer tickets by making them hard to file

## Validation gate

Stable process; exception path; metric is not concealment.

## Final principle

If the exception is the process, you are not ready to automate. You are ready to redesign.
